# DES Case Lab

DES Case Lab — демонстрационное приложение для фиксации, просмотра и сравнения результатов экспертных AI-моделей.

Проект разработан как двухдневный MVP: он показывает полный сценарий работы аналитического журнала и дашборда как с локальными данными, так и через собственный HTTP API и серверное хранилище.

## Назначение

Приложение позволяет сохранять экспертные кейсы, отслеживать результаты разных моделей и получать сводную статистику по накопленным данным.

Каждый кейс содержит:

- название или краткое описание;
- модуль: `Genre`, `Scene`, `Photo` или `Text`;
- модель: `Sol`, `DeepSeek` или `Astra`;
- ответ модели;
- статус: `Принят`, `Ошибка` или `На проверку`.

## Возможности MVP

- создание, редактирование и удаление кейсов;
- подтверждение перед удалением;
- журнал кейсов в виде таблицы на desktop и карточек на mobile;
- фильтрация по модели, модулю и статусу;
- комбинирование фильтров по принципу AND;
- сброс активных фильтров;
- KPI по общему количеству кейсов и статусам;
- автоматически пересчитываемая статистика по моделям;
- демонстрационные данные при первом запуске;
- отдельные пустые состояния для пустого журнала и фильтров без результатов;
- адаптивный тёмный интерфейс;
- CRUD через HTTP API;
- серверное хранение кейсов в Neon Postgres;
- Vercel Functions для обработки API-запросов;
- состояния загрузки, ошибки и повторного запроса;
- защита от повторной отправки формы и повторного удаления во время запроса;
- явный выбор источника данных: `api` или `local`;
- сохранение локальных данных в LocalStorage в режиме `local`;
- резервное сохранение повреждённых локальных данных перед восстановлением.

## HTTP API

- `GET /api/cases` — получить список кейсов;
- `POST /api/cases` — создать кейс;
- `PUT /api/cases/:id` — обновить кейс;
- `DELETE /api/cases/:id` — удалить кейс.

API возвращает frontend-модель `ExpertCase` с полями `createdAt` и `updatedAt`. Внутренние SQL-имена полей не передаются в UI.

## Архитектура

Основной API-режим:

```text
UI
 ↓
useCases
 ↓
CaseRepository
 ↓
ApiCaseRepository
 ↓
HTTP API
 ↓
Vercel Functions
 ↓
Neon Postgres
```

Альтернативный локальный режим использует ту же абстракцию:

```text
UI → useCases → CaseRepository → LocalCaseRepository → LocalStorage
```

Компоненты не обращаются напрямую ни к HTTP API, ни к LocalStorage. Конкретная реализация выбирается явно через `VITE_DATA_SOURCE=api` или `VITE_DATA_SOURCE=local`.

Автоматического переключения на LocalStorage при сетевой ошибке нет.

## Конфигурация окружения

Файл `.env.example` содержит безопасный шаблон необходимых переменных. Для локальной работы создайте исключённый из Git файл `.env.local` и задайте в нём значения:

```dotenv
VITE_DATA_SOURCE=api
VITE_API_BASE_URL=/api
DATABASE_URL=<Neon connection string>
```

- `DATABASE_URL` — серверная секретная переменная подключения к Neon. Её нельзя добавлять в Git или использовать в клиентском коде.
- `VITE_DATA_SOURCE` и `VITE_API_BASE_URL` — frontend-конфигурация. Переменные с префиксом `VITE_` попадают в клиентскую сборку и не должны содержать секреты.

Для локального режима установите `VITE_DATA_SOURCE=local`. В этом режиме `DATABASE_URL` не используется.

## Локальный запуск

Требуется актуальная версия Node.js и npm.

Установите зависимости:

```bash
npm install
```

Для запуска frontend и Vercel Functions в полном API-режиме:

```bash
npx vercel dev --listen 4173
```

После запуска приложение доступно по адресу `http://localhost:4173`.

Для запуска только frontend в локальном режиме с `VITE_DATA_SOURCE=local`:

```bash
npm run dev
```

## Ограничения MVP

- авторизация и многопользовательские роли не реализованы;
- приложение предназначено для демонстрационных несекретных данных;
- пользователь с доступом к развёрнутому приложению может изменять общие демонстрационные кейсы;
- внешние AI API не вызываются, ответы моделей вводятся вручную;
- автоматического fallback с API на LocalStorage нет;
- автоматической миграции существующих локальных кейсов в Neon нет;
- данные LocalStorage относятся только к конкретному браузеру, а данные API-режима хранятся отдельно в Neon;
- очистка данных сайта или LocalStorage удалит локальный журнал, но не затронет данные Neon.
