# DES Case Lab

DES Case Lab — демонстрационное локальное приложение для фиксации, просмотра и сравнения результатов экспертных AI-моделей.

Проект разработан как MVP: он показывает базовый сценарий работы аналитического журнала и дашборда без подключения backend или внешних API.

## Назначение

Приложение позволяет сохранять экспертные кейсы, отслеживать результаты разных моделей и получать сводную статистику по накопленным данным.

Каждый кейс содержит:

- название или краткое описание;
- модуль: `Genre`, `Scene`, `Photo` или `Text`;
- модель: `Sol`, `DeepSeek` или `Astra`;
- ответ модели;
- статус: `Принят`, `Ошибка` или `На проверке`.

## Возможности Day 1

- создание, редактирование и удаление кейсов;
- подтверждение перед удалением;
- журнал кейсов в виде таблицы на desktop и карточек на mobile;
- фильтрация по модели, модулю и статусу;
- комбинирование фильтров по принципу AND;
- сброс активных фильтров;
- KPI по общему количеству кейсов и статусам;
- автоматически пересчитываемая статистика по моделям;
- сохранение данных между перезагрузками через `LocalStorage`;
- демонстрационные данные при первом запуске;
- резервное сохранение повреждённых локальных данных перед восстановлением;
- отдельные пустые состояния для пустого журнала и фильтров без результатов;
- адаптивный тёмный интерфейс.

## Стек

Для визуализации статистики используются адаптивные CSS-бары без дополнительной библиотеки графиков.

## Архитектура

Работа с данными отделена от компонентов интерфейса:

```text
UI
 ↓
useCases
 ↓
CaseRepository
 ↓
LocalCaseRepository
 ↓
LocalStorage
```

Компоненты не обращаются к `LocalStorage` напрямую. Они работают через `useCases` и асинхронный контракт `CaseRepository`.

Такая абстракция позволяет на Day 2 реализовать `ApiCaseRepository` и подключить backend без полной переработки форм, таблицы, фильтров, KPI и статистики.

## Локальный запуск

Требуется актуальная версия Node.js и npm.

Установите зависимости:

```bash
npm install
```

Запустите локальный сервер разработки:

```bash
npm run dev
```

После запуска Vite выведет локальный адрес приложения в терминале.

## Ограничения Day 1

- backend отсутствует;
- внешние API не используются;
- авторизация и многопользовательский режим не реализованы;
- данные хранятся только в `LocalStorage` конкретного браузера;
- данные не синхронизируются между браузерами и устройствами;
- очистка данных сайта или LocalStorage удалит локальный журнал.

## План Day 2

- реализовать `ApiCaseRepository`;
- подключить backend/API;
- добавить полноценные состояния загрузки, сетевых ошибок и повторных запросов;
- определить стратегию переноса локальных данных;
- подготовить и выполнить развёртывание.

Day 2 остаётся демонстрационным MVP с несекретными данными. Авторизация в его рамках осознанно не реализуется: пользователь, имеющий доступ к опубликованному приложению, сможет изменять демонстрационные кейсы.
